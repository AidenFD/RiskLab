## 5. V1 scope and defaults

Implement one to ten USD assets, fixed nonnegative share quantities,
nonnegative cash earning zero interest, positive initial prices, one to 252
future session steps, and correlated Gaussian DAILY LOG returns. Fractional
holdings are allowed: this is valuation, not an execution simulator.

Provide both estimated historical log means and a ZERO_LOG_MEAN mode. Use
ZERO_LOG_MEAN as the initial UI default to make historical drift extrapolation
an explicit choice. Explain that zero log mean does not imply zero expected
arithmetic return or zero expected price change.

Starting configuration: 10,000 primary paths, 252 steps, an explicit fixed
example seed, batch size 512, and confidence levels 95% and 99%. Validate all
limits and tail requirements before starting. Publish the final supported
limits and resource policy; do not silently accept arbitrarily large requests.

V1 excludes shorts, borrowing, leverage, rebalancing, cash interest, FX,
transaction costs, execution, live trading, options, derivatives, margin,
dividend payment processing, split processing, and automatic market downloads.
Reject unsupported position types rather than treating them as ordinary stock.

Total-return indices, block bootstrap, time-varying covariance, jumps,
volatility clustering, and named deterministic shocks are later extensions.
Do not quietly add them before the baseline is verified. Comparing low and
high volatility is supported through explicit parameter scenarios; do not
assign probabilities to a named stress event without a model that defines them.

Reject duplicate or empty symbols, duplicate JSON keys, unsupported currencies,

## 10. Alignment and calibration

Each matrix row represents one complete adjacent session interval and each
column one identified asset. Match symbols before converting to arrays.
Validate against declared expected sessions; a missing required session or
multi-session gap is an error. A Friday-to-Monday interval is adjacent only
when the declared calendar says so. Reject gaps in a declared interval instead
of hiding them through an intersection operation.

For adjacent prices compute g[t,i] = log(P[t,i] / P[t-1,i]). Use the same
complete dates for all assets. Do not include estimation data after the
snapshot date. Report price rows, usable return observations, first/last
interval, and missing-data diagnostics.

Estimate daily log means and sample covariance with denominator n - 1 and
assets in columns. Handle the one-asset covariance shape explicitly. As an
engineering floor, require at least max(60, 10 times asset_count) complete log
return observations for historical calibration. Record this choice and explain
that it is not a statistical guarantee. Manual test models do not need
fabricated history to bypass this requirement.

ZERO_LOG_MEAN changes only the applied mean, not the historical sample
covariance estimate. Store estimated means and applied means separately.
Do not recenter covariance around zero as if zero were the sample mean.
Keep daily parameters daily. Annualized figures are display-only, with their
session-count convention labeled.

## 11. Manual parameter scenarios

Provide a versioned manual model JSON and a usable editor/import workflow for
deterministic, low-volatility, high-volatility, and singular-correlation tests.
Use ordered daily log means and a daily log covariance matrix, with explicit
symbol labels. Validate through the same covariance policy as calibrated data.

Do not require users to enter arbitrary matrix elements for the main demo;
presets and simple, properly validated controls are appropriate. Advanced
manual covariance input must identify dimensions and units clearly. Editing
a model creates a new scenario; it does not change a published result.

## 12. Covariance validation and factorization

Check dimensions, finiteness, symmetry, and eigenvalues before drawing any
shocks. Reject materially asymmetric or indefinite matrices. Declare the
symmetry tolerance and relative PSD tolerance, with a small absolute floor
in daily-variance units. Do not use an unexplained large absolute tolerance
that can swallow meaningful negative eigenvalues in small daily covariances.

Tiny negative eigenvalues within that declared tolerance may be clipped to
zero. Record original and effective matrices, eigenvalues before/after,
tolerances, corrections, numerical rank, and factorization method. Do not
silently add diagonal jitter, shrink covariance, replace correlation, or repair
materially invalid inputs into a different model.

Support singular positive-semidefinite matrices, including zero covariance
and perfectly correlated assets. Use an eigenvalue factorization or another
verified PSD method; ordinary Cholesky alone is insufficient [1].

For Sigma = Q diag(lambda) Q-transpose, a factor is
B = Q diag(sqrt(clipped_lambda)); verify B B-transpose matches effective
Sigma. For row-oriented independent normal draws Z, use Z B-transpose.
Test orientation explicitly. Undefined correlation for zero-variance assets
must be N/A with a reason, not a fabricated zero or invalid JSON number.

## 13. Return model and valuation

For each future session, sample g ~ Normal(m, Sigma), independently across
time and correlated across assets within the session. Update
S_next[i] = S_current[i] times exp(g[i]). m already is mean log return:
DO NOT subtract one-half variance again. An arithmetic-drift GBM interface
would be a different future contract.

For every path and step, V = cash + sum(quantity[i] times S[i]). Cash and
share quantities stay fixed. Include step zero. Compute the running equity
peak and maximum proportional drawdown for each path as it progresses.

Check numerical finiteness and positivity after operations. Overflow,
underflow to unusable zero prices, or invalid valuation must fail explicitly
with batch/step context; do not clip, discard affected paths, or publish a
biased result. Distinguish model-generated Gaussian tails from numeric errors.

## 14. Asset order and reproducibility

Keep the user's declared asset order visible and persisted. Maintain explicit
identifier-based mappings among portfolio, returns, mean, covariance, and
shocks. Never rely on accidental dictionary or CSV column ordering.

To satisfy the design's same-seed permutation fixture, use a documented
canonical internal symbol order for factorization and random consumption,
then map outputs back to the declared order. Record both orders and mappings.
Permuting only labels must not silently change portfolio economics.

Use an explicit NumPy Generator and named BitGenerator, such as PCG64, rather
than process-global random state. Record seed, generator, NumPy/Python/build
information, sampling algorithm, factorization, batching, and effective model.
Promise repeatability only under the same documented execution environment
and random-call contract [2]. A seed alone is not a universal guarantee.

Do not claim batch-size invariance unless proved. It is acceptable for batch
size to be part of the reproducibility contract. UI rendering, sorting,
preview selection, and uncertainty diagnostics must not consume the main
simulation RNG. Use explicitly derived independent streams and record their
derivation; avoid ad hoc seed-plus-one assumptions for independent checks.

## 15. Batching and bounded memory

Do not allocate the full paths-by-steps-by-assets tensor for normal runs.
Process bounded batches, retaining current asset prices, running portfolio
peaks, per-path maximum drawdown, terminal values, and a small display subset.
Use vectorization within batches instead of Python loops over every path.

Choose preview path IDs reproducibly without perturbing the simulation stream.
Store their full equity paths, path IDs, and selection rule. Capture preview
paths during simulation; do not rerun an inconsistent separate process for
the chart. Summary statistics must use every completed primary path, never
only the preview subset.

If the path chart shows a preview envelope, label its subset size. Do not call
it a full-population percentile band. Full-path quantile bands are optional
only with a tested, budgeted aggregation method and clear exact/approximate
semantics. Sample minima and maxima are not guaranteed future bounds.

## 16. Exact loss, VaR, ES, and drawdown definitions

Let V0 be initial equity, VN each terminal equity, and loss L = V0 - VN.
Gains are negative losses. Do not floor VaR or expected shortfall at zero.

For N sorted ascending losses and confidence alpha in (0,1):

- k = ceil(alpha times N), using one-based indexing.
- VaR(alpha) is sorted_loss[k - 1] in zero-based code.
- q = ceil((1 - alpha) times N).
- ES(alpha) is the mean of the q largest losses.
- Probability of loss is count(VN < V0) / N, using a strict inequality.
- Its approximate Monte Carlo SE is sqrt(p times (1-p) / N).

Use exact decimal/rational confidence arithmetic for k and q, or a thoroughly
tested equivalent. Binary rounding must not turn a 100-observation tail into
101 at a boundary. Export alpha, k, q, indexing and tie conventions. Do not
replace this finite-sample ES with another fractional-tail convention without
explicitly changing and documenting the source contract.

Maximum drawdown is max over steps of (running_peak - current_equity) divided
by running_peak, calculated separately within each full path including step
zero. Then summarize those per-path drawdowns with a declared quantile method.
It is not the drawdown of the median path or of the mean equity curve.

Report terminal equity and loss distributions, means/medians and useful
quantiles, VaR/ES in dollars and fraction of V0, loss probability, and drawdown
quantiles. Use distinct labels for terminal loss risk and path drawdown risk.

## 17. Tail sufficiency and uncertainty

For a normal published risk run, require at least 100 observations in EVERY
selected tail. At 99% confidence this requires at least 10,000 paths under
the stated convention. Reject insufficient configurations before sampling;
show the minimum needed and preserve the user's form. Low-level summarizer
tests can use tiny fixtures without pretending they are adequate estimates.

Show path count, tail count, horizon, confidence, seed, and probability SE.
At p = 0 or 1, explain that the plug-in SE being zero does not establish
certainty. Provide a suitable binomial interval, such as Wilson, for loss
probability and document its confidence level.

Implement a separate uncertainty/stability diagnostic for VaR and ES. A
reasonable v1 is empirical bootstrap intervals over ALL primary terminal
losses with a separately seeded diagnostic RNG, plus independently seeded
repeat simulations. Document resampling count, interval rule, and limitations;
resample the complete loss sample, not only the observed tail. Bound memory
by processing resamples incrementally.

Provide a working Check Stability action using at least two additional
independent simulation streams at the same portfolio, model, horizon, path
count, and confidence settings. Report each replicate separately, including
seed derivation and tail count. Do not silently pool these into the primary
N or replace primary results.

Choose and document a defensible rule for materially unstable tail estimates,
using sampling uncertainty and a stated monetary scale rather than dividing
by a nearly zero VaR. Show a warning when triggered. If diagnostics were not
run, show NOT ASSESSED; if cancelled, show INCOMPLETE. Never display STABLE
solely because the minimum tail count was met. Diagnostic intervals describe
Monte Carlo sampling under this model, not total real-world risk uncertainty.

## 18. Scenario comparisons

Support low-volatility versus high-volatility and zero-log-mean versus

Common random numbers may be used for controlled sensitivity comparisons

replicates for stability assessment. Never silently conflate the two.

Display actual computed results, not an assertion that every finite random
sample must rank in the expected order. Do not call a scenario comparison
a strategy backtest or a portfolio optimizer.

## 19. State and invariant checks

For zero covariance and zero mean, preserve constant values. For all-cash
exposure, preserve cash equity regardless of asset shocks. Ensure changing
preview size, table order, chart refresh rate, or screen navigation cannot

## 22. Worker ownership and run lifecycle

One worker owns each simulation and its private mutable arrays. The main Qt
thread owns widgets. Freeze validated inputs before starting; communicate
through signals and immutable snapshots. Never mutate widgets from a worker
or simulation arrays from the GUI [4].

Use clear states such as EMPTY, INVALID, READY, RUNNING, CANCELLING,
COMPLETED, CANCELLED, and FAILED. Prevent duplicate workers and stale result
signals replacing newer runs. Starting a new run creates a new identity.
Preserve the last completed result during an invalid new edit.

Implement Run and Cancel. Check cancellation within bounded work intervals,
not only after an entire expensive run. Progress must reflect actual work
and distinguish primary simulation, diagnostics, and saving. Do not fake a
timer-based percentage. Chart updates may be throttled to approximately
10-20 Hz, with bounded transport memory and no skipped numerical computation.

Do not add exchange replay speeds or manual order queues merely because
OrderBookLab had them. Pause/resume is optional only if it preserves generator
state and has meaningful verified semantics. It is not required for v1.

## 33. Exact acceptance fixtures
